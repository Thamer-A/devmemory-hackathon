What DevMemory does

1 · Scan

Reads the project once: files, functions, the require graph, Roblox remotes, config keys, and conventions it observes in the code. 0 LLM tokens, about 25 ms.

2 · Capture

Records each AI session through Claude Code's documented JSON output: prompts, visible replies, tool calls, edits and file hashes.

3 · Pack

For a new task, builds a small context pack (about 700 tokens) of the files, past sessions and decisions that matter, each with its source.

4 · Freshness

Compares every remembered edit with the current code line by line. When the code has since changed, the memory is flagged STALE instead of being trusted.

What the data says

  • History is the big win. B1 ("implement the daily reward we planned last session") passes only with full DevMemory (3/3). Every other setup goes 0/3, Sonnet included.
  • The static map alone is not enough. C2 (map only, 79%) is no better than a hand-written CLAUDE.md. Still, the scanner found all 5 planted project conventions with no human effort and no LLM calls.
  • The freshness check did not change pass rates. With stale flags turned off, the stale tasks still passed 6/6, because the agent reads the current code anyway. We'll report this as it is.
  • One weak spot: A2 (add a shop item) sometimes misses registering the icon in the asset manifest, in every condition.

What was built today

  • Telemetry check: headless claude -p reports tokens, list-price cost, turns, tool calls, and even your quota meter. Runs are isolated so your settings and connectors don't leak in.
  • DevMemory CLI: devmem scan / run / import / pack / status / hook. The hook injects the pack into normal interactive Claude Code sessions.
  • P1 "CoinRush": a synthetic Roblox (Rojo/Luau) game, 27 files. It has 5 real captured past sessions and a later hand-made refactor that makes 2 of them stale.
  • P2 "ledgerly": a Python app with 56 tests, built the same way and used only for held-out testing.
  • Benchmark harness: automatic graders, a runner (conditions × tasks × repeats), reports, and re-grading from saved diffs.
    • Every grader is checked: it fails on the unmodified project and passes on a reference solution.
    • The held-out tasks were written by a separate agent that I never read from, then hash-frozen.
  • Quota used: about 250 runs moved your 7-day meter from 18% to 19%.
